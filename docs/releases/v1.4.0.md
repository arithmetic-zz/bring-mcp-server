# v1.4.0 — Shopping previews, cross-list search and writable attributes

Resolves issues #21–#27.

- `get_lists` supports JSON and MCP structured content while retaining default text output.
- New `search_items` finds items across all accessible lists using the existing case, whitespace and German spelling normalization, with list/item identities and open/history status.
- Mutation tools support `dry_run` with the same target resolution and validation as execution, without sending writes.
- Restoring a history item reports `restored` and retains its UUID and omitted specification.
- `batch_update` accepts per-item operations overriding a global default of ADD. All targets are preflighted before one bulk request, with effective operation and status per result.
- `attributes` on adds and explicit batch `ATTRIBUTE_UPDATE` write validated `{type, content}` attributes through the supported Bring payload. List JSON attributes are no longer silently discarded.
- Explicit UUID/name mismatches fail with an unsupported-rename error instead of silently ignoring the requested name change.

Existing canonical and legacy aliases remain supported. A preview does not reserve state, and preflight is not atomic with concurrent edits by other clients. Automated tests mock Bring access and verify SDK request serialization; no live shopping lists are changed by the test suite.

Downloads are built for Linux x86_64, Windows x86_64, macOS arm64 and macOS x86_64. Publication requires successful source tests, builds and offline MCP smoke tests for every extracted archive. SHA256SUMS accompanies all four downloads.
